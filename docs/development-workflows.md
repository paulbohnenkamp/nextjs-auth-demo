# Development workflows

Run these commands from the repository root.

## First-time setup

```bash
cp .env.example .env
npm install
docker compose up -d
npx prisma migrate deploy
npm run db:seed
npx playwright install chromium
```

Replace the example `SESSION_SECRET` in `.env` with a value generated by:

```bash
openssl rand -base64 32
```

## Normal development

Start PostgreSQL and the Next.js development server:

```bash
docker compose up -d
npm run dev
```

The application is available at <http://localhost:3000>.

Browse all repository documentation at <http://localhost:3000/docs>. Run `npm run docs` whenever TSDoc comments change so the generated API reference stays current.

Stop the Next.js server with `Ctrl+C`. Stop and remove the PostgreSQL container while preserving its data:

```bash
docker compose down
```

To stop PostgreSQL without removing its container:

```bash
docker compose stop
```

## Inspect or edit database data

Ensure PostgreSQL is running, then start Prisma Studio:

```bash
docker compose up -d
npx prisma studio
```

Open <http://localhost:5555> if it does not open automatically. Studio exposes the `User`, `Session`, and `OnboardingSession` tables.

## Prisma schema and migrations

After editing `prisma/schema.prisma`, create and apply a development migration:

```bash
npx prisma migrate dev --name describe_the_change
```

Regenerate Prisma Client after schema or dependency changes:

```bash
npx prisma generate
```

Apply committed migrations without creating a new migration:

```bash
npx prisma migrate deploy
```

Validate schema and migration state:

```bash
npx prisma validate
npx prisma migrate status
```

## Seed demo users

```bash
npm run db:seed
```

The seed is idempotent. Both accounts use `DemoPassword1!`:

- `complete@example.com` has a complete profile.
- `incomplete@example.com` enters profile completion after login.

## Run checks and tests

Run individual checks:

```bash
npm run format:check
npm run lint
npm run typecheck
npm test
npm run test:e2e
npm run build
```

`npm test` includes database integration tests, so PostgreSQL must be running and migrated. Playwright starts Next.js automatically but also requires PostgreSQL.

Run the full local verification sequence:

```bash
docker compose up -d
npx prisma migrate deploy
npm run db:seed
npm run format:check
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

## Reset local database data

The following command permanently deletes the Compose database volume:

```bash
docker compose down -v
```

Recreate the database afterward:

```bash
docker compose up -d
npx prisma migrate deploy
npm run db:seed
```

Do not use `docker compose down -v` when you need to preserve local data.

## Production-style local run

```bash
npm run build
npm start
```

Use production-quality environment values before deploying. Production releases should apply migrations with `npx prisma migrate deploy`, not `prisma migrate dev` or `prisma db push`.

## Troubleshooting

- **Database connection refused:** run `docker compose ps`; if PostgreSQL is absent, run `docker compose up -d`.
- **Port 5432 is occupied:** change the host-side Compose port and update `DATABASE_URL` in `.env`.
- **Schema and client disagree:** run `npx prisma generate`, then restart the development server.
- **Seed login fails:** rerun `npm run db:seed` and use the documented password exactly.
- **Browser tests cannot launch:** run `npx playwright install chromium`.
- **Start from clean dependencies:** run `npm ci` when `package-lock.json` is authoritative.
